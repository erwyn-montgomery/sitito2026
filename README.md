Код исследования «Влияние показателей сложности текста на формирование батчей для классификации большими языковыми моделями». 

Датасеты: 
* Fake News;
* Yahoo! Answers;
* GoEmotions. 

Целевые модели: 
* `qwen3.5-4b`;
* `ministral3-3b`;
* `gemma4-e4b-it`. 

Показатели сложности: 
* `flesch_kincaid`;
* `ppl`;
* `knn_distance`;
* `label_margin`;
* `predictive_entropy`.

Алгоритмы группировки: `bfd`, `diff_close`, `diff_diverse`, `diff_routing`. Алгоритмы упорядочивания: `random`, `diff_edges`, `diff_disperse`. `bfd/random` — общий контроль без выбора метрики; остальные 11 сочетаний используют выбранную метрику. `k` — максимум документов.

Подробные таблицы с результатами находятся в директории `tables/`: [Qwen3.5-4B](tables/reviewer_qwen3.5-4b.csv), [Ministral3-3B](tables/reviewer_ministral3-3b.csv), [Gemma4-E4B](tables/reviewer_gemma4-e4b-it.csv). Токены указаны как доля расхода от однодокументного контроля. Отдельная таблица [«Однодокументная классификация»](tables/single_doc_baselines.csv) содержит Macro-F1 и абсолютную сумму входных и выходных токенов для каждой модели и датасета.

Обозначения G-DiffHom, G-DiffDiv и G-DiffRout соответствуют `diff_close`, `diff_diverse` и `diff_routing`; O-DiffEd и O-DiffDiv — `diff_edges` и `diff_disperse`.

## Окружение

Необходим Python 3.11+ и POSIX-система. Команды ниже предназначены для будущего запуска на вычислительном сервере из корневой директории репозитория.

```bash
pip install -r requirements.txt
cp .env.example .env
```

PyTorch следует выбирать с учётом CUDA вычислительного сервера.

В `.env` задайте отдельные `*_BASE_URL`, `*_API_KEY`, `*_SERVED_MODEL` с префиксами `QWEN35`, `MINISTRAL3`, `GEMMA4`. Для сервера без авторизации явно укажите ключ `EMPTY`. Пустой endpoint или ключ вызывает ошибку перед инференсом. Реальные ключи, адреса с секретными параметрами и `HF_TOKEN` храните только в окружении.

Настройки генерации по умолчанию: температура 0, максимум 7000 выходных токенов, контекстное окно 65536, параллелизм 16. Значение attempts — общее число соответствующих попыток, включая первую. При необходимости его можно увеличить. Параметры `ModelConfig` читаются из переменных `<ПРЕФИКС>_<ИМЯ_ПОЛЯ>`; полный список находится в `config.py`. Например, `MINISTRAL3_TRANSPORT_ATTEMPTS=2`.

`--seed` управляет батчингом и не передаётся автоматически модели. Дополнительные параметры запроса задаются в `*_REQUEST_OPTIONS_JSON`, параметры шаблона — в `*_CHAT_TEMPLATE_KWARGS_JSON`.

Пути задаются аргументами CLI или переменными `<ДАТАСЕТ>_CSV`, `<ДАТАСЕТ>_METADATA`, `<ДАТАСЕТ>_FEW_SHOT`. Аргумент имеет приоритет. `OUTPUT_ROOT` задаёт каталог результатов. Относительные пути отсчитываются от текущей рабочей директории. Для другого файла окружения используйте `python cli.py --env-file /srv/difficulty/settings.env ...`. Уже заданное окружение имеет приоритет над `.env`.

## Данные и ресурсы

Датасеты нужно разместить в директории `data/`, по одной поддиректории на датасет: `fake_news`, `yahoo`, `goemotions`.

CSV должен содержать уникальный непустой строковый `index`.

Примеры настроек для использованных датасетов:
| Датасет | Поля для метрик | Поля для классификации | Gold для Macro-F1 |
| --- | --- | --- | --- |
| `fake_news` | `title`, `text` | `title`, `text`, `date` | `label` |
| `yahoo` | `title`, `content`, `answer` | `title`, `content`, `answer` | `class_label` |
| `goemotions` | `text` | `text` | `class_label` |

В классификационный payload входят только поля из соответствующего столбца таблицы. Fake News использует `true = REAL`, `false = FAKE`. Yahoo требует точные имена классов. Для GoEmotions эталонная метка — строковое представление списка или перечень точных имён через запятую. Онтология содержит 28 меток, включая `neutral`, и хранится в `resources/label_descriptions.json`. Для подготовки метрик эталонные метки не нужны.

Для kNN/LM нужна матрица документных эмбеддингов `.npy` размера N×d и отдельные ID: одномерный Unicode `.npy` либо JSON-массив. ID должны покрывать весь CSV ровно по одному разу. Порядок матрицы проверяется и выравнивается по ID. Object-dtype `.npy` принимается только с явным `--trusted-pickle-ids` для доверенного файла.

Для PPL нужны веса `Qwen/Qwen3-0.6B`. Для PE нужны `cross-encoder/nli-deberta-v3-small`. Вспомогательные модели загружаются через Hugging Face или из локального каталога. Доступ и веса обеспечивает пользователь.

Few-shot файл — JSON-объект с ключами `in` и `out`. Оба значения — объекты с одинаковыми строковыми ID, не пересекающимися с исследуемым корпусом. `in` использует payload соответствующего датасета; `out` — JSON булевы значения для Fake News, строки для Yahoo, массивы строк для GoEmotions. Путь задаётся через `--few-shot` или соответствующую переменную окружения. Используйте один файл примеров во всех сравниваемых условиях.

## Вычисление эмбеддингов

Модель задаётся переменной `FEATURES_EMBEDDING_MODEL` в `.env`. Для исследования используется `Qwen/Qwen3-Embedding-8B`; можно указать другую модель, совместимую с `SentenceTransformer`, или локальный путь к ней.

```bash
python cli.py embed --dataset yahoo \
  --csv data/yahoo/source.csv \
  --embeddings data/embeddings/yahoo.npy \
  --embedding-ids data/embeddings/yahoo_ids.json
```

При необходимости модель можно передать через `--embedding-model`: аргументы имеют приоритет над `.env`. Те же аргументы доступны у `prepare`. Для обеих команд используйте одинаковые настройки.

Команда читает `index` и поля для метрик из таблицы выше, соединяет очищенные непустые поля двумя переводами строки и кодирует документы через `SentenceTransformer.encode`. Используются `normalize_embeddings=True`, `convert_to_numpy=True`, без дополнительных инструкций. `token_len` и истинные метки для этой команды не нужны. Если длины ещё не рассчитаны, на следующем шаге используйте `prepare --count-tokens` с выбранным токенизатором.

Результат — матрица `.npy` с типом `float32`, JSON-массив строковых ID в том же порядке и файл `<датасет>.metadata.json` рядом с матрицей. В метаданных сохраняются настройки модели, поля текста, размерность, время расчёта и хэши. Другой путь к ним можно задать через `--embedding-metadata`.

Передайте матрицу и ID следующей команде `prepare`. Метаданные эмбеддингов подхватываются автоматически по имени матрицы. Ксли они находятся отдельно, укажите `--embedding-metadata`. При загрузке проверяются тексты, соответствие ID и векторов, хэши и настройки кодирования.

## Подготовка метрик

Пути ниже условные, замените их своими. При использовании примеров не задавайте конфликтующие пути к метаданным в `.env`.

```bash
python cli.py prepare --dataset yahoo \
  --csv data/yahoo/source.csv \
  --output-csv data/yahoo/prepared.csv \
  --embeddings data/embeddings/yahoo.npy \
  --embedding-ids data/embeddings/yahoo_ids.json \
  --metrics all
```

Команда вычисляет все пять метрик из исходного CSV и записывает `prepared.csv` и `prepared.metadata.json`. Входной CSV не перезаписывается. Метаданные содержат параметры расчёта, revisions, хэши документов и метрик, время вычисления и версии библиотек.

Можно выбрать отдельные метрики, например `--metrics flesch_kincaid knn_distance`. Каждый вызов вычисляет выбранный набор заново; выходной CSV содержит только этот набор метрик. Для нескольких наборов используйте разные выходные файлы.

Для последующей классификации передайте созданный CSV и его `--metadata`. Код проверяет ID, длины, хэши, параметры и канонические описания классов.

### Подсчёт токенов документов

Добавьте к команде `prepare` флаг `--count-tokens` и укажите токенизатор через `--length-tokenizer`:

```bash
python cli.py prepare --dataset yahoo \
  --csv data/yahoo/source.csv \
  --output-csv data/yahoo/prepared.csv \
  --embeddings data/embeddings/yahoo.npy \
  --embedding-ids data/embeddings/yahoo_ids.json \
  --metrics all --count-tokens \
  --length-tokenizer /srv/tokenizers/qwen3.5-4b
```

Токенизатор должен быть доступен локально. Путь или имя можно также задать в `FEATURES_LENGTH_TOKENIZER`.

Считаются поля для классификации из таблицы выше: непустые значения очищаются по краям и соединяются двумя переводами строки. Токенизация выполняется без специальных токенов и без обрезания текста.

До вычисления метрик программа выводит число документов и сумму их токенов. Длины записываются в выходной CSV, параметры подсчёта — в `prepared.metadata.json`. Итог команды также содержит `token_len_total` и `token_len_documents`. Для сравнения моделей используйте один подготовленный CSV: выбор токенизатора определяет длины, по которым формируются батчи.

## Классификация

```bash
python cli.py single --dataset yahoo --model qwen3.5-4b \
  --csv data/yahoo/prepared.csv \
  --few-shot data/yahoo/examples.json \
  --output-root results

python cli.py batch --dataset yahoo --model qwen3.5-4b \
  --csv data/yahoo/prepared.csv \
  --metadata data/yahoo/prepared.metadata.json \
  --few-shot data/yahoo/examples.json \
  --grouping diff_diverse --ordering random --difficulty ppl --k 8 16 \
  --output-root results
```

Для полной классификации одного датасета укажите `--model all --grouping all --ordering all --difficulty all --k 2 4 8 16 32 64`. Это 56 условий на модель и `k`: один независимый контроль и 11×5 условий с метриками. Датасеты выбираются отдельными командами. Сначала выполните `prepare --metrics all`.

## Абляция

По умолчанию команда только готовит условия, без API-запросов:

```bash
python cli.py ablate --dataset yahoo --model all \
  --csv data/yahoo/prepared.csv \
  --metadata data/yahoo/prepared.metadata.json \
  --few-shot data/yahoo/examples.json \
  --output-root results/ablation
```

Один манифест на `(датасет, метрика, seed)` используется всеми моделями, обеими алгоритмами и всеми `k`. Десять страт строятся исходной сортировкой `(token_len, string ID)` и разбиением на почти равные последовательные группы. Манифест перестановки сохраняет исходную оценку, "донора" и назначенную оценку. Настройки по умолчанию: seed для перестановок 101/202/303, алгоритмический seed 42, `diff_diverse/random` и `bfd/diff_edges`, `k=8,16,32,64`.

В том же вызове добавьте `--execute` для инференса переставленных условий.

## Результаты и токены

Обычный результат сохраняется в:

```text
OUTPUT_ROOT/<model>/<dataset>/<grouping>__<ordering>/<metric-or-control>/seed_<seed>/k_<k>/result.json
```

Для раздельной (однодокументной) классификации используются `single_doc__identity/control/k_1` после директории seed. В абляции вместо алгоритмического seed в пути стоит `permutation_<seed>`; рядом с результатом лежат `plan.json` и `diagnostics.json`.

`result.json` содержит предсказания по строковым ID, Macro-F1 в шкале 0–1, входные и выходные токены и сумму, окончательные ответы батчей, ошибки документов, версии правил, настройки, хэши и идентификатор запуска. При одинаковом условии новый полностью завершённый запуск атомарно заменяет предыдущий целиком. Предсказания и токены разных запусков не объединяются. Неудачный запуск возвращает ненулевой код и не перезаписывает прошлый успешный результат.
